# Kling 4.0 プロンプト記法ガイド

Kling 4.0 に固有の書き方（ショットの区切りと秒数、ワンカット、キーフレーム、万能リファレンスの `@` タグ、編集の定型文、セリフと音声、画面内の文字、除外指定）をまとめる。カメラの動きは [camera-movements.md](camera-movements.md)、レンズと被写界深度は [lens-and-focus.md](lens-and-focus.md)、ショットサイズ・アングル・構図は [shot-composition.md](shot-composition.md)、光と色は [lighting-color.md](lighting-color.md)、複数ショットの連続性は [multi-shot-continuity.md](multi-shot-continuity.md) を参照する。数値条件の一覧と出典は [source-guide.md](source-guide.md) にある。

**確度の表記**：各項目に確度を付ける。

- **【公式】** Kling公式ページで本文を確認したもの。Kling 4.0 のリリースノート（[source-guide.md](source-guide.md) の §1）と、kling.ai の 3.0／3.0 Omni／O1 のユーザーガイド・公式ブログ。**3.0以前の資料に由来する項目には「（3.0時点）」のように世代を添える。** 4.0で名称や上限が変わっている可能性があるので、画面で確認する。
- **【第三者】** 公式情報を解説する第三者記事などで、複数の独立した情報源が一致するもの。公式の一次文面は未確認。
- **【未確認】** 情報源が単一、または裏付けが弱いもの。このSkillの提案（目安）もここに含める。ユーザーへ断定して伝えない。

**【第三者】【未確認】の項目をユーザーへ説明するときは、公式で未確認であることを添える。数値や仕様を発明しない。**

## 1. モデル・世代の取り違えに注意（最重要）

Web上には Kling 1.x〜3.0 向けの助言が多く残っている。**4.0 と 4.0 Flash の条件で書き、古い世代の尺やモードの助言を当てはめない。**

| 項目 | 1.x〜2.x 時代の公式ガイド | 3.0／3.0 Omni（公式、3.0時点） | **Kling 4.0**（公式） | **Kling 4.0 Flash**（公式） |
|---|---|---|---|---|
| 尺 | 5秒か10秒を選ぶ | 3〜15秒の任意 | **3〜30秒** | **3〜20秒** |
| 解像度 | Standard／Professional モード | 720p／1080p（4Kモードの案内あり） | **720p／1080p／4K**。1080p・4Kで10bit HDR（本文では「近日対応予定」） | **720p、8bit SDR** |
| 縦横比 | 16:9／9:16／1:1 | — | **21:9／16:9／1:1／9:16／スマート** | 記載なし |
| 開始・終了フレーム | 対応 | 対応 | 始終フレーム対応。**キーフレーム最大10枚** | **開始フレームのみ**の記載 |
| 音声 | リップシンクは別機能 | ネイティブ音声、5言語 | **2chステレオ**、多言語・方言・アクセント（§7） | 記載なし |
| 参照素材 | Elements | 画像最大7、動画1本 | **万能リファレンス合計15点まで**（§5） | 万能リファレンス対応（上限の記載なし） |
| プロンプト長 | — | — | **8,000トークン以内** | 記載なし |

- 旧ガイドの「5〜10秒で完結する簡単な内容にする」「5秒か10秒を選ぶ」は1.x〜2.x時代の条件。**4.0の尺の設計には使わない。** 「簡単な語と文型で書く」「数に弱い」のような書き方の助言は引き継いでよい（§2）。
- **Flash で使う場合は20秒以内・720pに収める。** キーフレームや終了フレームを使う構成は、Flash の画面で対応を確認してから出す。
- **他モデル向けの括弧記法（`( )` 音楽、`< >` 効果音、`{ }` セリフ、`【 】` 字幕など）を持ち込まない。** Kling の公式資料にはない書式である。Kling では §7 の話者ラベル形式で書く。

## 2. プロンプトの骨格

Kling 公式の基本式（**【公式】**、テキストから動画のガイド）。

```text
Prompt = 主体（主体の描写） + 主体の動き + 場面（場面の描写） + （カメラ言語 + 光 + 雰囲気）
```

- 必須は**主体・動き・場面**の3つ。括弧内は任意で、必要な分だけ足す。
- 主体・場面の描写は短い文を複数並べる（髪型と色、服装と小物、表情、姿勢など）。
- 参照素材を使うときの式（**【公式】**、O1時点）：`[各素材の詳しい描写] + [素材どうしの相互作用・動作] + [環境・背景] + [光・スタイルなどの見た目]`
- 複数ショットは、**先に場面（設定）を定義し、続けてショット順に並べる**（**【公式】**、公式ブログ）。

4.0 の公式ページは「シンプルなプロンプトから、練り込んだ複雑なプロンプトまで幅広く対応」し、「プロンプトを的確に解釈・補足・ブラッシュアップ」すると説明する（**【公式】**）。作例のプロンプトも「AIについて不満をぶちまける老人」のような一文から、「N秒間のワンカット。場所。人物と出来事。周囲の様子。」のような短い段落までである。

- **書いていない要素はモデルが補う前提で考える。** 固定したい要素（人物の特徴、立ち位置、光の向き、セリフ、除外したいもの）は明記し、任せてよい要素は書きすぎない。
- 8,000トークンまで入力できても、長いほど良いわけではない。完成したプロンプトは「短いショット指示書」として読めることを目安にする。

書き方の助言（**【公式】**、旧ガイドと公式ブログ）。

- 簡単な語と文型を使う。
- 「magic」のような曖昧な語ではなく、「青いエネルギーの粒子が渦を巻き、淡く光る」のように画面に見えるものを書く。
- 動きは見える変化で書く（煙が上へ流れる、炎が風で曲がる、走者が前傾する）。
- **数に弱い。** 「砂浜に10匹の子犬」のような個数は保たれにくい。個数が重要なら少数にするか、後編集を提案する。
- 跳躍・落下・投擲のような物理的な動きは、**踏み切り → 空中の弧 → 着地 → 接地**のように段階を書く。

## 3. ショット構成と秒数

### 生成モード（**【公式】**、3.0時点）

| モード | 動作 |
|---|---|
| Multi-Shot オフ | 既定で単一ショット（カットなし）を生成する |
| Multi-Shot オン | プロンプトからショットの切り替え・画角・構図をモデルが計画する。単一ショットのほうが合う内容なら、モデルが柔軟に調整する |
| Custom Multi-Shot | Multi-Shot オンが前提。ショット数と各ショットの秒数を設定し、ショットごとに内容を書く。プロンプトに厳密に従う |

- 3.0 では1回の生成で最大6カット（**【公式】**、公式ブログ）。**4.0（最長30秒）でのショット数の上限は未確認。** 画面の上限を確認する。
- 4.0 の公式ページは「カメラの動きや複数カットの構成をより正確に理解」「ショットサイズの切り替えやシーン間のトランジションも滑らかにつながる」と説明する（**【公式】**）。モード名が4.0の画面で同じかは確認する。
- 第三者の解説には「Custom Multi-Shot を使うときはメインのプロンプト欄を空にし、各ショット欄に書く」とするものがある（**【未確認】**）。画面の仕様に従う。

### 公式の作例に見られる書式（**【公式】**、3.0時点）

| 書式 | 例 |
|---|---|
| ショット番号＋秒数 | `Shot 1 (2s): Wide shot, @Boxer A and @Boxer B face off ...` |
| タイムコード | `[00:00 - 00:02] Medium shot: ...` |
| ショット番号＋サイズ | `[Shot 1: Wide shot] A futuristic female pilot walking ...` |
| 番号だけ | `Shot 1, Low-angle rear wide shot, tracking behind the rider ...` |

このSkillでは、**秒数を指定するなら `Shot 1 (3s):`、順序だけなら `Shot 1:`** を既定にする。1つのプロンプト内で書式を混在させない。

### 守る条件

- **秒数は整数で書き、ショットの秒数の合計を生成尺の設定に一致させる**（このSkillの方針。**【未確認】**）。公式の作例も、各ショットに整数秒を割り当てている。
- **1ショット＝1主要アクション＋主要カメラ移動1つ**（多くても方向が矛盾しない2つまで）。
- 公式の作例には1〜2秒のショットもある。ただし**セリフや主要な動作を含むショットは3秒以上**を目安にする（このSkillの提案。**【未確認】**）。セリフは自然に読む速さで収まるかを確認する。
- 各ショットの冒頭にショットサイズ・アングル・カメラを書き、切り替えは `Cut to a close-up of ...` のように示す（**【公式】**の作例の型）。
- ショットが変わるたびに、人物を `@タグ` または同じ識別特徴で再指定する（§5）。

30秒の配分の目安（このSkillの提案。**【未確認】**）。

| ショット | 役割 |
|---|---|
| Shot 1 (6s) | 状況を提示する（establish） |
| Shot 2 (8s) | 展開する（develop） |
| Shot 3 (9s) | 転じる（turn） |
| Shot 4 (7s) | 収める（settle） |

## 4. ワンカット（長回し）とキーフレーム

### ワンカット

- 公式の作例は `Long take.`、`one continuous long take without any cuts`、`This is a 15-second cinematic long take, a single unbroken shot with no edited transitions.` と書く（**【公式】**、3.0時点）。4.0の公式ページの作例も「N秒間のワンカット。」で始まる（**【公式】**）。
- **Multi-Shot を使わずに生成する**（オフで単一ショット。**【公式】**、3.0時点）。
- ワンカットの中で時間を示すときは、**文中で秒を指す**（**【公式】**の作例の型）。
  - `At the 4th second, the camera accelerates forward with her ...` / `In the final 3 seconds, ...`
  - 日本語なら `4秒目で、カメラが彼女と一緒に加速して前進する。` `最後の3秒で、...`
- 1つの進化する運動として書く。始まりと終わりのある弧を描き、無関係な動作を積み重ねない。
- 被写体とカメラの同期を書く（公式の作例：歩くとカメラが追い、止まるとカメラも止まる）。
- 4.0 は「1回のネイティブ生成で最長30秒」「長回しや連続したストーリー展開に対応」と説明される（**【公式】**）。

### キーフレーム（4.0）

- **最大10枚のキーフレーム画像**に対応する（**【公式】**。仕様表の「フレキシブルキーフレーム」）。人物の状態、場面の変化、物語の節目など、動画が通るべき瞬間を画像で固定し、その間の動きをモデルが補う。
- **キーフレームをプロンプト内でどう指すか（タグ名・番号）は未確認。** 画面の表示に合わせる。
- プロンプトには、**キーフレーム間で何が変わり、何が原因か**を順番に書く（このSkillの提案。**【未確認】**）。
  - 例：`キーフレーム1→2：少女が窓辺から振り返り、ドアへ歩き出す。カメラは slow dolly out。キーフレーム2→3：...`
- 隣り合うキーフレームは同じテーマ・似た構図にする。**差が大きいとカットが入りやすい**（**【公式】**、始点・終点フレームの助言）。
- 終了フレームだけを指定する生成は非対応（**【公式】**、O1時点）。
- 3.0 では、開始フレーム／始終フレームの生成に最大3つの被写体（要素）を紐づけて一貫性を高められる（**【公式】**、3.0時点）。紐づけるのは開始フレームに写っている被写体が推奨。

## 5. 万能リファレンス（参照素材）と `@` タグ

### 4.0 の上限（**【公式】**、仕様表）

| 種別 | 上限 |
|---|---|
| 画像 | 合計10枚以下 |
| 動画 | 合計5本以下、素材動画の合計30秒以内（動画内の被写体を含む） |
| 音声 | ボイスリファレンスのみ対応 |
| 被写体 | 合計7体以下（複数画像の被写体・動画の被写体を含む）。動画内の被写体は3体以下 |
| 合計 | 画像・動画・音声・被写体を合わせて15点まで |

上限まで使うことを推奨しない。役割が重なる素材は減らす。

### 使える参照の種類（**【公式】**、4.0 の公式ページ）

- **画像**：被写体画像、三面図、グリッド画像、インフォグラフィック、キーフレーム、ワイヤーフレームなど（公式ページの作例には絵コンテやゲーム画面の参照画像もある）。被写体の見た目、シーン構成、映像スタイル、文字・グラフィック要素、カメラ構図、重要なストーリー展開まで指定できるとされる。
- **動画**：キャラクターの演技や動作、カメラワーク、ストーリーのテンポを再現できる。**ホワイトモデル（白い3Dモデル）の動画やデプスマップ（深度）動画**にも対応する。
- **被写体（要素）**：人物・商品・小物などの再利用できる素材。**被写体には音色（声）を指定できる。**
- 公式ページの作例の組み合わせ：複数キャラクターの参照画像、商品画像＋参照動画、動作の参照動画＋参照画像、カメラワークの参照動画＋参照画像、ホワイトモデルの参照動画＋参照画像。

### `@` タグの書き方

- 画面の入力欄で `@` を打つと、追加済みの素材や被写体を呼び出せる（**【公式】**、3.0時点）。公式の作例は `@Grace`、`@Boxer A`、`@Image`、`@Image1`、`@Video` のように書き、角括弧で囲む `[@Banana Cat]` の表記もある（**【公式】**）。
- **被写体名は登録名と完全に一致させる。** 名前に空白を含む場合や、直後に日本語の助詞が続く場合は、`[@Little Scholar]が` のように角括弧で囲むと境界がはっきりする（このSkillの提案。効果の差は**【未確認】**）。
- 公式APIの説明として、**互いに部分文字列になる名前（`@Zhang` と `@ZhangSan`）を避ける**、**本文と重なる名前（メールアドレスを書くのに `@gmail`）を避ける**、APIでは `@image_1`・`@video_1` の形式、という報告がある（**【第三者】**）。サードパーティのAPIには `<<<image_1>>>` の形式もある。利用するサービスの記法に合わせる。
- テキストとして貼り付けた `@名前` が画面上で素材に紐づくかは、画面で確認する。紐づかない場合は `@` の候補から選び直す（**【未確認】**）。

### 役割を文中で明示する

**素材を並べるだけでは、どの素材が何を制御するのかが伝わらない。** 各素材に1つの役割を与え、文中で宣言する（**【公式】**、公式ブログ「各リファレンスに明確な役割を」）。

```text
@Aoi は主役の研究者（顔・髪型・服装・声）を定義する。
@Image1 は研究所の背景とライティングを定義する。
@Video1 はカメラワーク（ゆっくり回り込む動き）だけを参照する。人物と背景は参照しない。
```

- 画像なら「どの見た目の特徴を参照するか」、動画なら「動作・カメラワーク・テンポのどれを参照するか」を書く。
- **再登場点でアイデンティティを再宣言する。** ショットが変わって人物が再び映るとき、`@タグ` と識別特徴（年齢・髪型・服）を短く再掲する。人物が多いほど必要。
- 服装・髪型・小物・場面での役割を安定した言葉で書き続けると一貫性が上がる（**【公式】**、公式ブログ）。
- 実際にアップロードされる素材の名前・順序に合わせる。**未提供の素材を存在するものとして書かない。**

### 被写体（要素）の作り方（**【公式】**、3.0時点）

- 複数画像の被写体：2〜4枚（正面のメイン1枚＋別角度の補助1〜3枚）。正面画像を推奨。
- 動画の被写体：3〜8秒の単独人物の動画から、外見と声を抽出する。
- 人物の被写体には声を紐づけられる（5〜30秒の1人の話し声を推奨。雑音・重なった声・大きな音楽がないもの）。
- **声を紐づけた被写体は、プロンプトで声色を再指定しない**（**【公式】**）。話し方（ささやく、驚いて）だけを書く。

## 6. 編集・参照生成の定型文

4.0 は「元動画の被写体や背景を追加・変更・削除」「スタイルや天候、色味、質感、ショットサイズ、視点なども調整」できるとされる（**【公式】**）。公式ページの作例には、**被写体の追加とセリフの変更**、人物・シーンの置き換え、複数キャラクターの置き換え、要素の削除、スタイル変更がある。

動画編集の入力条件（**【公式】**、仕様表）：動画は最大5本（うち1本をメイン動画として指定）、1本あたり3〜30秒、合計30秒以内、参照画像との併用を推奨。

以下の構文は O1 の公式ガイドのもので、3.0 Omni の編集機能は O1 と同じとされる（**【公式】**、O1／3.0時点）。4.0 でも有効と見込まれるが、画面で確認する。

| 目的 | 公式の構文 |
|---|---|
| 追加 | `Add [追加する内容] from @Image1 to @Video1` ／ `Add @Element to @Video1` |
| 削除 | `Remove [削除する内容] from @Video1` |
| 画角・構図の変更 | `Generate [another angle/composition, e.g. close-up, wide shot] in @Video1` |
| 被写体の変更 | `Change [対象] in @Video1 to [変更後]` ／ `... to @Element` ／ `... to [変更後] from @Image1` |
| 背景の変更 | `Change the background in @Video1 with [背景の描写]` ／ `... with @Image1` |
| 部分の変更 | `Change [対象の部分] in @Video1 to [変更後]` |
| スタイル変換 | `Change @Video1 to [アニメ、羊毛フェルト、水彩など] style` ／ `Change @Video1 to the style of @Image1` |
| 色の変更 | `Change the [物] in @Video1 to [色]` |
| 天候・環境 | `Change @Video1 to [a rainy day など]` |
| グリーンバック | `Change the background in @Video1 to a green screen, and keep [残す内容]` |
| 次のショット | `Based on @Video1, generate the next shot: [ショットの内容]` |
| 前のショット | `Based on @Video1, generate the previous shot: [ショットの内容]` |
| カメラワークの参照 | `Take @Image1 as the start frame. Generate a new video following the camera movement of @Video1` |
| 動作の参照 | `Animate the character in @Image1 with the same motion as the character in @Video1` |
| 開始フレーム | `Take @Image1 as the start frame, [以降の変化]` |
| 始終フレーム | `Take @Image1 as the start frame, take @Image2 as the end frame, [2枚の間の変化]` |

運用ルール（このSkillの方針）。

- **構文の骨格（Add / Remove / Change / Based on ... / Take ... as the start frame）は英語の型を保ち、[ ] の中は日本語で具体的に書いてよい。** 意図どおりに出ないときは中身も英語にした版を出す。
- 変更する対象、**変更前 → 変更後**、**維持する周辺要素**（人物、カメラ、光、音）を明示する。
- セリフを変更するときは、新しいセリフにリップシンクの3規則を適用し、話者を明示する。
- 公式は複数の編集の組み合わせ（被写体の追加＋背景の変更、スタイル変更＋被写体など）にも対応すると説明する（**【公式】**、O1時点）。失敗したら1つずつに分ける。

### 延長

- 4.0 は、アップロードした動画の続きを何度でも生成でき、**最長2分まで延長可能**とされる。**公式ページの表記は「近日公開予定」**（**【公式】**）。提供状況は画面で確認する。
- 旧ガイドの「延長のプロンプト＝主体＋動き」「元動画と無関係な文はカットや転換を招く」という助言は引き継いでよい（**【公式】**、旧ガイド）。元の末尾の人物・物体・移動方向から続け、連続撮影か場面転換かを明記する。旧ガイドの「4〜5秒ずつ、合計3分まで」は旧世代の条件なので使わない。

## 7. ネイティブ音声：セリフ・話者・言語・音

### 対応範囲（**【公式】**、4.0 の仕様表と本文）

- 音声：**2chステレオ**。リップシンクの精度が向上し、「音声・セリフ・演技が自然にシンクロ」するとされる。
- 対応言語：**中国語、英語、日本語、韓国語、スペイン語、ポルトガル語、ドイツ語、フランス語、ヒンディー語など**。
- 方言・アクセント：中国語（北京訛り、台湾訛り、東北方言、四川方言、広東語など）、英語（アメリカ英語、イギリス英語、インド英語など）。
- 3.0時点では、対応外の言語で書いたセリフは英語に翻訳されるとされた（**【公式】**、3.0時点）。

### 書き方（**【公式】**の作例と公式ブログの助言）

- **話者・セリフ・話し方を近くにまとめる。** 公式の作例の型：
  - `Mom (softly, in a surprised tone): Wow, I didn't expect this plot at all.`
  - `@Grace says, "Hey! Watch your dog!"`
  - `Boy (casual tone, Korean): "숙제 다 했어?"`
  - 日本語のセリフは英語の文の中に `「急いで作ったけど、大丈夫？」` のようにかぎかっこで置かれている。
- 言語・方言・アクセントは話者に付ける（`speaks in English with an Indian accent`、`said in Cantonese`）。
- ナレーション：`Voiceover (lazy French female voice, British accent, slow pace): ...`
- 複数話者は、各セリフを話者名と対にする。3人以上でも話者とセリフを対応づけられるとされる（3.0時点）。
- 同じ場面で話者ごとに言語を切り替えられる（3.0時点）。

このSkillの書式。

```text
話者ラベル（話し方、言語）：「発話する語だけ」
```

- 例：`@Aoi（ゆっくり、喜びを抑えた口調、日本語）：「2,000時間のけんさんが、ついに実を結びました。」`
- **かぎかっこの中は発話する語だけにする。** 言語・声質・話し方はかっこの外に置く。
- **リップシンクの3規則（難読漢字→ひらがな／数値→算用数字／英語→カタカナ）は、かぎかっこの中のテキストに適用する。** `@タグ`・ファイル名・URL・画面に表示する文字は改変しない。
- **声を紐づけた被写体には声色を書かない**（§5）。話し方・感情だけを書く。

### リップシンクを安定させるコツ（**【公式】**、公式ブログ）

- 話す人物の顔が見えるショットサイズ・向きにする。
- 文法を単純にし、長い文は短いセリフに分ける。
- 話し方の注記（ささやく、驚いて、低い声で）は場面に必要なときだけ付ける。
- 被写体の声の参照素材は、声の重なりや大きな音楽がないものを使う。

### 環境音・効果音・音楽

- 括弧記法は使わず、**平文で音の環境を書き、映像の動作と組み合わせる**（**【公式】**）。例：`リビングのエアコンのかすかな音が続く`、`with soft French piano BGM in the background`。
- 公式の作例には、各ショットに `Audio:` の行を置いて音を書く型がある（**【公式】**、3.0時点）。このSkillでもショットごとの音は `Audio:` の行にまとめる。
- ユーザーが言っていないセリフや音楽の要否を、全件共通の禁止事項にしない。

## 8. 画面内の文字

- 4.0 は中国語・英語・日本語・韓国語・スペイン語・ポルトガル語・ドイツ語・フランス語・ヒンディー語などのテキストと、**絵文字・ロゴ**を鮮明かつ安定して生成でき、画面の動きやシーンの切り替えの中でもテキストの鮮明さを保つとされる（**【公式】**）。
- 表示する文字は、**正確な語、置く場所、書かれている面、カメラとの距離**を書く。読みやすさが重要なら文字は短くする（**【公式】**、公式ブログ）。
  - 例：`The camera remains fixed on the word "KLING" emblazoned on the baseball bat.`（公式の作例）
  - 例：`店の看板に "OPEN" の白い文字。画面右上、看板は正面向き、medium shot で読める大きさ。`
- **セリフと画面の文字を区別する。** セリフは必ず話者ラベル＋かぎかっこ（§7）、画面の文字は「看板に "..." の文字」「〜と書かれている」の形で書く。画面の文字にはリップシンクの3規則を適用しない。
- 精度は上がっているが、ロゴや細かい文字の完全な保持は保証しない。必要に応じて後編集を提案する。

## 9. 除外指定（ネガティブ）

- Kling の画面やAPIには、除外したい要素を本文とは別に書く**ネガティブプロンプト欄**が用意されてきた（**【第三者】**、主に3.0以前のAPI）。**4.0 の画面での有無は未確認。**
- **欄がある場合**：除外したい要素を名詞で並べる（`subtitles, text overlay, jump cut, camera shake, blur`）。否定語（`no`）は付けない（一般的な運用。**【未確認】**）。
- **欄がない場合**：本文の末尾に `no subtitles`、`no background music` のように平文で書く。
- **ユーザーが求めていない禁止事項を足さない。** 除外が必要な理由があるときだけ書く。

## 10. 公式ガイドが例示する語彙と言語

Kling 公式のガイド・作例に現れる英語の語彙（**【公式】**。主に3.0時点。4.0 の公式ページもプッシュ・プル・パン・ドリー・フォロー・オービットを挙げる）。

| 区分 | 語彙 |
|---|---|
| ショット | `extreme close-up`, `close-up`, `medium close-up`, `mid-shot` / `medium shot`, `full body shot`, `wide shot`, `establishing wide shot`, `long shot`, `macro shot`, `profile shot` |
| アングル・視点 | `low angle`, `high angle`, `eye level`, `frontal`, `side view`, `top-down shot`, `bird's-eye view`, `first-person POV`, `over the shoulder` |
| 動き | `push-in` / `dolly-in`, `pull back`, `pan`, `tilt`, `zoom`, `tracking shot`, `follow`, `orbit` / `circles around`, `360-degree pan`, `handheld`, `the camera rises` |
| 構成 | `long take`, `Cut to ...`, `shot-reverse-shot`, `cross-cutting`, `voice-over` |
| レンズ・画 | `ultra-wide angle`, `telephoto`, `bokeh` / `blurred background`, `depth of field`, `motion blur`, `tilt-shift` |
| 光 | `ambient lighting`, `morning light`, `sunset`, `golden hour`, `rim light`, `Tyndall effect`, `god rays`, `haze` |
| 構図 | `centered`, `rule of thirds`, `off center`, `symmetrical composition` |

- 旧世代の画面には、プロンプトとは別に**カメラの動きを操作するパネル**（horizontal、vertical、zoom、pan、tilt、roll の6種＋4つのマスターショット）があった（**【公式】**、旧ガイド）。4.0での提供は未確認。使う場合は本文のカメラ指示と矛盾させない。
- 上の一覧にない珍しい用語は、**用語＋対象の被写体＋見た目の変化＋前景／背景の関係＋方向または速度**で説明を添える。

### プロンプトの言語

- 公式の作例は英語・中国語で書かれたものが多く、日本語のセリフは英語の文の中にかぎかっこで置かれている（**【公式】**、3.0時点）。4.0 の日本語の公式ページには日本語の作例プロンプトが載っている（**【公式】**。原文か翻訳かは不明）。
- 日本語のプロンプト入力には対応するが、**複雑なカメラワークやスタイル指定は英語のほうが意図どおりになりやすい**とする解説が複数ある（**【第三者】**、主に3.0）。
- このSkillの既定は**「英語の撮影用語＋日本語の演出文」**。ユーザーが英語を望む場合、または日本語で意図どおりに出ない場合は、**演出文を英語にした版**を出す。どちらの場合もセリフは日本語のまま（3規則を適用）。

## 11. 避けること

- `cinematic`、`4K`、`masterpiece` のような語だけで済ませる。品質の語は解像度の設定の代わりにならない。解像度・縦横比・尺は画面で選ぶ。
- 「カメラを動かす」のような物理的な手がかりのない指示。
- 矛盾するカメラ指示の重ね合わせ（`handheld` と `locked steady` を同時に、右へパンした直後に左へホイップパンして急降下、など）。
- 1ショットに無関係な動作を3つ以上積む。
- 個数に頼る（「10匹の子犬」）。
- 旧世代の尺・モードの助言や、他モデル向けの括弧記法を持ち込む。
- 曖昧な形容詞に頼る。完成したプロンプトは「短いショット指示書」として読めるべきで、写真のキャプションではない。
